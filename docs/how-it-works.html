How it works

Cloakroom checks what goes to the AI and swaps real values for placeholders.

In short

Every time the AI reads a file, runs a command or uses an add-on, Cloakroom checks what goes to the AI and swaps real values for placeholders. When the AI writes or runs something that holds a placeholder, Cloakroom puts the real value back on your machine. Commands that would send a secret off your machine, or move money, wait for your OK.

Words used below: hooks are small checks the agent runs before and after each action (a “tool call”). PII is personal data such as names, emails and addresses. MCP tools are add-ons that give the agent extra abilities, such as a browser. OCR reads text out of pictures. The vault is an encrypted file on your machine that holds the real values for one session.

  Claude Code reads a file or runs a tool
        |   "Nadia Petrov called about..."    sk_live_51Hx9Q...
        v
  +--------------------------------------------+
  | Cloakroom  (on your machine)               |
  |   rules + local model  ->  find the values |
  |   encrypted vault      ->  remember them   |
  +--------------------------------------------+
        |   "PII_PERSON_1 called about..."    PII_SECRET_1
        v
  the model works with placeholders only
        |   Write reply.md: "Hi PII_PERSON_1,"
        v
  Cloakroom puts the real value back, locally
        |
        v
  reply.md on your disk: "Hi Nadia Petrov,"

The two modes

Full (the default)
Runs pattern rules and an AI model on your machine (PII-Tracer). It catches keys, passwords, card numbers, government IDs, and also names, addresses and other personal details written as plain text.
Rules
Runs the pattern rules only. It still catches keys with a known shape (AWS, GitHub, Stripe, Slack, OpenAI, Google, JWT login tokens, private keys), numbers with a built-in check digit (cards, IBANs, SSNs) and emails or names next to an obvious label, but it misses most personal data in ordinary sentences. Use it when you can’t install the model, or when you only care about secrets.

Set the mode for everything in ~/.cloakroom/config.json, or for one shell with CLOAKROOM_MODE=rules, or for one command with --mode rules.

{ "mode": "rules" }

Backends (full mode only)

CLOAKROOM_BACKEND picks how the model runs. The default, auto, uses PyTorch when there’s a GPU (Apple Silicon or an NVIDIA card with CUDA), otherwise the ONNX export if you’ve made one, otherwise PyTorch on the CPU. ONNX is a model format that runs fast on a plain CPU.

  • cloakroom export-onnx writes the CPU model under ~/.cloakroom/onnx/. It needs PyTorch once and takes a few minutes (about 4 on a 2-core cloud machine).
  • CLOAKROOM_ONNX=int8 uses a smaller, lower-precision export: a little faster, a few more false alarms.
  • CLOAKROOM_BACKEND=torch or onnx forces one.

cloakroom doctor prints the backend in use and how long one check takes.

Each step

Hide

A hook checks what goes into each tool and what comes back out. It runs pattern rules for secrets with known shapes, numbers with a check digit, rules that read the words around a value, and the PII-Tracer model for names, addresses and other personal data in sentences. A prompt with sensitive data is blocked instead, since a prompt can’t be rewritten. A value found once is masked everywhere it repeats.

Filter

A known-safe filter leaves harmless look-alikes alone, such as documented examples: published test cards and keys, IDs from test (sandbox) accounts, reserved domains like example.com, bot and role mailboxes (noreply@, support@), loopback addresses (127.0.0.1), UUIDs and hashes, text that already hides a value ([REDACTED], ***), filler placeholders (AC000…, sk-...), standard numbers after RFC / ISO / ICAO / IEEE / PEP, and default dates (1970-01-01, 1900-01-01).

Pictures

PDFs become their text. Scans, pictures the agent opens and images in add-on tool results are read on your machine (OCR, the ocr extra), and only the masked text goes to the agent. Without the extra they are held back.

Put back (restore)

Values go into the vault. It is locked with AES-GCM, a standard encryption method, and its key sits in your system’s password store (Keychain on a Mac). When the agent writes a file or runs a command with a placeholder, the real value is put back locally. The AI never sees it.

Placeholders that can’t be guessed

A placeholder is PII_<KIND>_<n>_<tag>. The tag is a short code signed with a key from the vault, so it can’t be guessed. A value comes back only when the tag checks out and the placeholder is in this session’s vault. Anything else in placeholder shape stays as text. Three refused guesses in one session show you one line.

Files the agent wrote stay masked

When real values are put back into a file, the hook records per file its path, its SHA-256, size and time, and per value the byte position, the value’s SHA-256, kind and placeholder. The log (~/.cloakroom/filelog.bin) is encrypted like the vault and holds no values: they are read back from the file when needed.

Encoded dumps and secrets

od, xxd, base64 and spaced-out output are turned back into text and checked; a hit holds the output back (it isn’t passed on). Each secret already in the session vault is also looked for in its encoded forms (base64, URL-encoded and JSON-escaped), and as an MD5, SHA-1 or SHA-256 hash, as hex, and reversed.

Sending-data hold

Before a shell command runs, Cloakroom checks whether it can send data off the machine. If it does and it holds a known secret, a key the rules recognise, or a literal token of 16+ characters in a login header (such as Authorization), the command is denied. To send it anyway, type cr: allow as your prompt (the agent never sees it), then ask the agent to run the same command again: it passes once, within 10 minutes.

Money-movement hold

Before any tool call runs, Cloakroom checks whether it would move money: a write to a listed payment endpoint, a payment CLI command, or an MCP tool whose name carries a money verb (such as pay or create_payout). Such a call is held with one line naming the endpoint or tool; cr: allow lets the same call run once.

Write-time and commit check

When a key or password would land in a file that is in a git repo and not git-ignored, the call is denied and the agent is told to put the value in .env. Before the agent runs git commit or git push, a key or password in what would be committed holds the command.

If the program is missing, nothing gets through

If the cloakroom command is missing, the plugin blocks prompts and denies tool calls instead of letting data through.

Other coding agents

Codex and Gemini CLI can’t swap a tool’s output for a masked copy, so Cloakroom blocks the original and the AI reads the masked text in the block message. Cursor’s terminal agent can’t swap output either, so Cloakroom changes the input instead: a file read goes to a masked copy of the file, and a shell command runs inside Cloakroom, which prints only masked output.

Codex
cloakroom hook <event> --agent codex reads Codex’s hook input and turns the answer into Codex’s. Codex’s file edits (apply_patch) are restored and checked like Write. cloakroom install codex writes the four hooks into ~/.codex/hooks.json.
Gemini CLI
Gemini CLI uses its own tool names with Claude Code’s argument names, so --agent gemini first renames the tool. Gemini lets a call through when a hook times out, so with the model not loaded yet the hook doesn’t wait: it checks with the rules inside the hook itself. cloakroom install gemini writes these hooks as an extension of its own.
Cursor
Cursor’s terminal agent sends its own tool names (Shell, Read, Write) with its own events, so --agent cursor first maps them. A read is redirected to a masked copy kept in Cloakroom’s home; a command is wrapped in cloakroom cursor-run, which runs it and masks what it prints; add-on (MCP) output is replaced with a masked copy. A write that carries a placeholder is refused, because Cursor ignores a hook’s rewritten input there, and the agent is told to write through the shell. Cursor’s Grep tool is refused when it would show file contents.

What it protects against, and what it doesn’t: Security model. Every detail: docs-HOW-IT-WORKS.md.

More features

Shows which keys your agents saw

cloakroom exposure lists the keys and passwords Claude Code, Codex CLI, Gemini CLI and Cursor’s terminal agent saw, each as a hint (ghp_…LmPq), never the key, and ends with a “Rotate these” list: keys to replace with new ones. It lists only what Cloakroom detected.

Warns when a pull changes what your agent runs

cloakroom scan lists every command a repo’s agent and editor config would run and flags the setup the October 2026 npm worm used: an agent hook and an editor task that run each other’s files. After cloakroom install git-hook, each pull, checkout or merge that adds or changes such a command prints it. It warns, never blocks.

Hand the agent a key safely

cloakroom give NAME asks for the value in a hidden terminal prompt and gives you a placeholder to paste. When the agent writes that placeholder into a local file or command, the real value goes back in. The AI never sees it.

Shows where your agent sends data

cloakroom report --destinations lists the sites your agent’s commands, web fetches and MCP calls went to, with the kinds of data they carried, and the dashboard shows the same in “Where data went”. cloakroom allow-host example.com builds an approved-sites list; once it is on, a call to any other site is held. An email, phone number, name or your username in a web address or header is held too.

Points any tool at Cloakroom

cloakroom proxy is a small server on your own machine for tools that let you set their API address, such as Claude Code, Codex CLI and Gemini CLI. Point the tool at it and every request is masked before it goes to the AI company; replies stream back unchanged. Off until you start it; Mac, Linux and Windows.

Updates with one command

Run cloakroom update in a terminal. It updates Cloakroom with the installer you used (uv, pipx or pip) and keeps the optional parts you had. Then it sets up Cloakroom’s checks again for Codex, Gemini CLI, Cursor’s terminal agent and git commits, only where they were set up before.

Takes stopped prompts out of the saved chat

Claude Code also saves every chat on your disk. A prompt Cloakroom stops is taken out of that saved copy for the current session (right away, after the next reply and when the session ends), so the key you typed doesn’t stay behind. Claude Code only.

Counts failed tool calls as not checked

A tool call that fails in Claude Code (for example a command with a non-zero exit) is counted as “not checked”: it shows in the event log, in “Checks skipped” in cloakroom report, on the dashboard, and as one note per session.
